# Review 5: a project at scale, plus the Python binding

Summary
- Maturity 2.5/5: single-file, single-namespace, one-adapter use is specified; five files, two namespaces, two products and a Python script expose holes in project model, instance paths, mangling and the Python operator/Result contract.
- Most important fix: define the project model (one project = one root, one lock, N namespaces, files map by header, `sources` may leave the root) and the instance-path rule for parameterized parts, because bindings, Python lookup and mangling all hang on them.
- Answer to OQ-11 as written: no reuse across projects is possible in 0.1.0; reuse inside one project is plausible but nothing in config-cli.md says it works.

Simulated project: `cad/company/{fasteners,wheels}.cdt` (namespace acme.company: AcmeShop FastenerPolicy, Caster ots parts), `cad/rover/{rover,axle}.cdt` (acme.rover), `cad/crawler/crawler.cdt` (acme.crawler); `cadetta.toml` with `[[adapter]] sw-equations` and an external `solidworks` adapter; `analysis/wall_sizing.py`; `report.py`.

## Findings

### 1. [blocker] config-cli.md 1, language.md 3-4, ir.md 3: "namespace" has three unrelated homes and no mapping rule
`[project] namespace = "acme.rover"` is singular, each file may carry `namespace X` (optional per the grammar), and `Project { namespace }` in the IR is singular. Nothing says what a file with no header gets, whether a file header must start with the project namespace, whether two namespaces can live in one project, what the IR `namespace` field holds for two, or whether `sources` globs may reach outside the toml's directory (`../company/**/*.cdt`).
Fix: add to config-cli.md a "Project model" section: (a) a project is the directory holding `cadetta.toml`; one lock file, one `build/`; (b) `[project] namespace` is only the default for files without a header, and `namespaces` in the IR becomes a list; (c) a file's namespace is its header, any dotted name, no relation to the directory; (d) `sources` are globs relative to the toml, may contain `..`, and are sorted by path before compile so digests are deterministic; (e) the same Type name defined twice in one namespace is an error (new code, see 9). State explicitly: "In 0.1.0 shared parts are shared by living in one project (a monorepo); cross-project reuse waits for OQ-11. A company library is a directory in `sources`."

### 2. [blocker] bindings.md 3.1 vs 3.3 vs "Result usage": infix operators cannot return Result
3.1 says Quantity arithmetic that violates kind rules "is a Result error carrying the Q-code". 3.3 writes `load * span / allowable` and then `.to_kind(...)` on the result. If `*` returns a Result, the second operator and `.to_kind` fail at runtime; Python operators cannot sensibly return Result. Also the 3.3 example is dimensionally wrong (N*m / Pa is a Volume, so the declared `Length` output can never pass) and `to_kind` is not a quantities.md operation (the language says `as`).
Fix: specify that operators (`+ - * / **`, comparisons) raise `cadetta.QuantityError(code="Q002")` (programmer-bug exception, consistent with the typani rule), and that `Result` is returned only by I/O and parse boundaries (`Project.open`, `evaluate`, `cadetta.quantity(text)`, queries). Rename `to_kind` to `as_kind` or `.cast("Length")` to mirror `as`, document it, and fix the example to a correct formula (e.g. `wall = (load * span / (allowable * width)) ** 0.5 ...` or simply `t = 6 * M / (allowable * width)` with units stated).

### 3. [blocker] adapters.md 3, bindings.md 3.1, language.md 3.1, ir.md 2: the example path `acme.rover::Axle.end_diameter` is not a valid path
README/language define `Axle(wheel, span)` as parameterized and instantiated as `part axle[2]: Axle(...)`; language.md 3.1 says reading a parameter-dependent member by type name is an error. Yet bindings.md 3.1 reads `Axle.end_diameter` from the evaluated design, adapters.md 3 binds it to a SOLIDWORKS global, and sw-equations.md uses `Gasket__width`. The real paths are `acme.rover::Rover/axle[0].end_diameter` and `[1]`. Which path does a binding attach to when two instances share one SOLIDWORKS part file? Does the file get two globals or one?
Fix: add to ir.md 2 an explicit rule: "Parameterized components exist only as instances. A binding may name `Rover/axle[*].end_diameter` (all instances; they share arguments, so the same value up to independent tolerance variables) or one instance. A `[*]` binding emits once, at the emit point of instance 0 (nominal differs by nothing), and an instance whose emitted value differs from instance 0 is R001-like error E-bind-divergent." Replace the examples in bindings.md and adapters.md accordingly.

### 4. [blocker] adapters.md 3 "Name mangling is injective": it is not, and the mangled form drops the namespace
Mangling shown is `Axle__end_diameter` and `Rover__wheel_2__hub_bore` (no namespace). `acme.rover::Axle` and `acme.crawler::Axle` collide in one equations file. Also `Rover/wheel[2].hub_bore` and a hypothetical fit member `Rover.wheel_2.hub_bore` mangle identically, and `Axle.seat.shaft` (fit member) vs an assembly-level path look alike.
Fix: mangle the full canonical path: namespace dots to `_`, `::` and `/` to `__`, `.` to `__`, `[i]` to `_i` is not injective either, so choose `[i]` to `__i` and forbid purely numeric segments; or hash-suffix on collision. Simplest rule: `acme_rover__Axle__end_diameter`, with `.` always `_` inside a namespace, `__` between all other segments, and add an emit-time collision check (new R-code or Q-style error) that is a hard failure. Update sw-equations.md examples. Also allow `[[adapter]] prefix = "..."` for readability.

### 5. [gap] bindings.md 1/3.1, ir.md 3: the Python Quantity cannot be built from the IR as specified, and the "returns exactly what the CLI JSON returns" promise is contradicted
`Value` has `nominal{r,pi}`, `angle`, `tol` but no dimension vector or unit; the Member has `kind` (a string such as `"Length"`, with no grammar for anonymous or compound kinds like `Volume/Time`, or currency dimensions). `.to("mm")` needs a dimension. Python also exposes `d.nominal`, `d.max`, `d.kind` while the JSON has `value.nominal`, `value.tol.terms`. `d.max` also requires summing Affine terms and `.mid`/`.mmc` need `role`. Variants (`Member.variants`) have no stated Python access.
Fix: add `dim: [int;7+currencies]` (or a canonical `kind_expr` string with a grammar) to `Value`. In bindings.md 3.1 state that `design[path]` returns a `Member` pydantic model (identical to JSON) whose `.value` is a `Quantity` wrapper with `.nominal/.min/.max/.mid/.mmc/.lmc` computed in the Rust core (not re-implemented in Python), plus `member.variant("Rover/wheel", "Colson2Series") -> Member | None` and `design.get(path) -> Result[Member, PathNotFound]` (not `[]` raising). Say `Quantity.to(unit)` returns `Fraction` if exact and `float` otherwise and the return is a union; better, `to_exact(unit) -> Fraction | None` and `to_float(unit) -> float`.

### 6. [gap] config-cli.md 1: no way to scope commands, adapters or solvers per product
With two products: `check`, `emit`, `sync`, `solve` have no `--namespace`/PATH filter (only `why`/`impact` take a PATH). `[[adapter]]` has one `out`; two products each linking their own SOLIDWORKS equations file need two `sw-equations` entries, but bindings live in `bindings/<adapter>.toml` (adapters.md 3) keyed by adapter name, so both entries share one bindings file and the lock's "last-sync digests per adapter and file" is ambiguous. `[solvers.wall_sizing]` is keyed by bare name while solvers are declared per namespace (collision across namespaces; also `<script>.out.json` beside a shared script collides when two products use one script with different inputs).
Fix: (a) `[[adapter]] id = "rover-sw"` (required when `name` repeats) plus `namespaces = ["acme.rover"]` or `paths = [...]` selecting what it emits; bindings file is `bindings/<id>.toml`; (b) `check/emit/sync/solve` take `--namespace NS` and positional canonical-path globs; (c) `[solvers."acme.rover::wall_sizing"]`; the result file is `<script>.out.json` keyed inside by solver path (already keyed by input digest per solvers.md 4.1, so say the file may hold several solvers).

### 7. [gap] config-cli.md 2: the CLI is not specified enough to implement or to wrap from Python
- Root discovery: `--cwd` exists, but is `cadetta.toml` found by walking up? There is no `--config`/`--project`. `Project.open(path)` in Python needs the same rule.
- `--format json` shapes: only `impact`, `compare`, `why` and the diagnostic have named schemas (obligations.md 5). `check`, `obligations`, `solve`, `emit`, `sync`, `import`, `ack`, `units`, `explain`, and `impact --swap` (seven ordered sections, a different shape from `impact PATH`) have none, while bindings.md 3.2 says Python models are generated from them. `impact --swap` needs its own `swap.json`.
- Exit codes: 1 is "diagnostics at or above fail_on" but is not defined for `why`, `impact`, `compare`, `obligations` (stale list non-empty?), `ack` (unknown selector), `fmt --check` (diff), `impact --swap` with verdict `blocked`, `solve` (S005 is a lint code, not an I/O error). `cadetta ack` of a path that matches nothing is 2 or 1?
- `json is the default when stdout is not a terminal` will surprise shell users piping to `less`; and the stdout/stderr split (JSON on stdout, logs on stderr) is not stated.
- `fail_on` has no listed values (`error|warning|info|never`?); `[obligations]` appears in obligations.md 4 but `[obligations.roles.source]` shows only two keys (`covers` glob grammar `ots:*`, `fit:*` is never defined; is it a class prefix or a path glob?); `required_for` values `check|release` only.
Fix: add a table per command: reads/writes, exit-code mapping (0 ok; 1 diagnostics or stale/blocked verdict; 2 usage/I/O), the JSON schema file name, and one example. Add a "Selectors" definition. State root discovery (walk up from `--cwd` to the first `cadetta.toml`, exit 2 if none) and add `--config`.

### 8. [gap] stdlib.md 4, language.md 3.11: a shop policy cannot be set for the project, only repeated per file
`#![default(FastenerPolicy = AcmeShop)]` scopes "every ScrewJoint in this file". With five files and two products every file that uses a joint must repeat the attribute, and a forgotten one silently falls back to `IsoDefault` with nothing flagging it. That defeats "override it for a whole scope without touching call sites" for the one scenario (a shop) the feature was built for.
Fix: add `[defaults]` to cadetta.toml: `FastenerPolicy = "acme.company::AcmeShop"` (qualified path), lower precedence than a file's `#![default]` and an enclosing component's, and a lint (info) when a `ScrewJoint` resolves to `std.fasteners::IsoDefault` while the project declares a policy of its own. State the precedence order in language.md 3.11.

### 9. [gap] language.md 3-4, lints.md: name resolution across files has no diagnostics and an ambiguous `use` grammar
The catalog has no codes for unresolved name or `use`, duplicate definition of a Type in one namespace (explicitly allowed: "several files may share a namespace"), `use` of a name not exported, import cycles between files, two `use`s bringing the same local name, or a `sources` glob that matches nothing. The grammar `use nspath "::" ( IDENT | { IDENT, ... } ) [ "as" IDENT ]` leaves `as` ambiguous after a brace list, has no wildcard (so `use std.fasteners::*` is unavailable and a company module with 30 parts needs 30 names), and `use std.fits::iso286` imports an item from a module that is itself a "namespace" without saying whether modules are files or namespaces. Visibility (private helper `fn`s in a company module) is not mentioned. I004 (root-not-evaluated, info) will also fire for every parameterized library part not used by a given product, which makes a shared module noisy.
Fix: add an "R: resolution" or "E: name" family (E001 unresolved name, E002 duplicate definition with both spans, E003 import cycle between files is allowed but declaration cycles are D003, E004 ambiguous import, E005 glob matched nothing) with fixed severity. Allow `use ns::*` and `use ns::{A as B, C}`. Add `pub` or state "everything is public in 0.1.0". Exempt components in namespaces other than the project's entry namespaces from I004, or make I004 apply only to components in files explicitly listed under `[project] roots`.

### 10. [gap] solvers.md 1-4, bindings.md 3.3: float handling, tolerance, relativity and Python helper are underspecified
- Outputs "MUST be literals with units; a decimal literal is exact; there is no other float path". A Python solver produces floats (`sqrt`), and the decorator must pick a literal. Which digits? `repr(float)` is exact-but-ugly (17 digits trip M001/D001 at the consumer) and round-trips as a rational. Add: the decorator emits `Decimal(str(x))` rounded to `significant=` digits (default 6) and a configurable `precision` per output; otherwise Q006 (inexact-value) fires at the consumer.
- Request carries `{"lit","si"}` only; a toleranced input `frame.span = 300mm [+-0.5mm]` loses its tolerance (`lit` could carry it, but the spec does not say). Say whether `lit` includes the bracket and offer `{"min","max"}` fields.
- Script path `@"analysis/wall_sizing.py"` is resolved against what (project root, the declaring file)? The same question applies to every file citation (digest-pinned), `deps`, and `bindings/`. Say: relative to the toml's directory.
- Input expression `frame.max_load` in the solvers.md example uses lowercase `frame` at file scope, while the prose says file scope names components (`Frame.span`); N006 would not even apply there. Fix the example.
- "writes the response with the solver's version" (bindings.md 3.3): the protocol has no `version` field; add an optional `version` to the response so it can enter the result digest.
- Result files are written beside the script; two solvers declared in two namespaces that use one script share `<script>.out.json`. See 6.

### 11. [gap] bindings.md 3.2/3.5: the Python surface is too thin for the stated workflow (open, evaluate, read, impact_swap, write a report)
Missing or inconsistent: how `Project.open` finds config, errors it can return (a typed `OpenError`?), `project.check()` returns `Result[CheckReport, ...]`, but is a project with error diagnostics Ok(report) or Err? (CLI exit 1 vs 2 gives the answer; say Err is only for I/O/usage); `impact_swap(slot, alternate)`: `slot` is a canonical path `acme.rover::Rover/wheel` and `alternate` a bare name or a path? A cross-namespace alternate (`acme.company::Colson2Series`) needs the qualified form, and `impact --swap PART NEW` in config-cli.md says nothing about the syntax either. There is no Python call for `solve`, `emit`, `sync`, `ack`, `obligations`, `ir`, `fmt`, so a report script that wants to know which CAD files go stale must shell out to `cadetta`, contradicting "every capability is reachable". `evaluate()` with one result per variant is not described; nor is mutability (`Project` caches? reload on file change?). Exact JSON-to-model parity: "pydantic models generated from the same JSON schemas" while `Quantity` is hand-written; `Fraction` is not JSON.
Fix: define the surface as a table: `Project.open(path|None, config=None)`, `.sources`, `.evaluate()`, `.check(release=False)`, `.why(path)`, `.impact(path)`, `.impact_swap(slot, alternate)`, `.compare(interface)`, `.obligations(stale=False, role=None)`, `.solve(names=None)`, `.emit(adapters=None)`, `.sync(...)`, `.ack(selector, role, reason)`, `.ir(observed=None)`; each returns `Result[Model, CadettaError]`; state `Err` is only for I/O, config or usage errors, never for design diagnostics. Define `slot` and `alternate` as canonical `Type/part` paths and (qualified) component names, and match config-cli.md `PART NEW`.

### 12. [polish] bindings.md 3.1 vs OQ-16; quantities.md 5.2; README table
3.1 says Quantity carries "optional tolerance" and "arithmetic ... follows the language's kind rules", yet OQ-16 asks whether Python arithmetic should carry tolerance at all; both cannot stand. `.max`/`.mid` are described as "returns an untoleranced quantity" in quantities.md but `d.max.to("mm")` in 3.1 shows `.to` returning a Fraction, so the accessor chain is fine but the return types of `.to` are inconsistent between `Fraction`, `float(...)` and a union. README Documents table does not list `docs/schemas/` and the config-cli.md section list has no entry for `cadetta.lock`, `bindings/*.toml` location, or `build/`.
Fix: close OQ-16 with an ADR in favour of carrying tolerance (the recommendation already says so; the 3.1 text assumes it) and delete the open question; fix the return-type wording; list every committed artifact (`cadetta.lock`, `bindings/*.toml`, `<script>.out.json`, `docs/schemas/`) in config-cli.md with its location rule.
