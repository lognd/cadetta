# Review 1: SOLIDWORKS adoption journey

Summary:
- Development of this area: 2/5. The data model (bindings, emit point, digests) is solid; the operational journey (import, sync, drift resolution, failure handling) is a sketch.
- Most important fix: make `sync` a three-way compare (lock base, design, observed) with a pre-push read, and store last-emitted values in the lock (finding 1).
- Counts: 4 blocker, 7 gap, 1 polish.

Journey walked: install, `init`, `import`, accept, cleanup, first `sync`, design change, SW-side edit (drift), resolve both ways, part swap, release.

## Findings

### 1. [blocker] adapters.md 2 (the loop), lints.md R001, obligations.md 3 - direct SW edits are overwritten before they can be detected
The loop is `compile -> lint -> push -> regen -> read back -> drift lint`. Drift is linted only after the push has already overwritten the user's edit, so a dimension edited in SW is silently clobbered and R001 can only compare the read-back with what was just pushed. R001 also promises "says which side moved", but the lock stores only "last-sync digests per adapter and file" (obligations.md 3), not the last-emitted value per locator, so the old value cannot be shown and a both-sides-moved case is undefined.
Fix: define `sync` as a three-way compare per locator with base = lock entry (`path locator emitted-value`, one sorted line each), ours = freshly computed emit value, theirs = a pre-push `read`. Table: ours==base and theirs==base: no-op; ours!=base, theirs==base: push; ours==base, theirs!=base: R001 "cad moved", do not push, exit 1; both moved and different: R001 "both moved", no push for that locator. Add `sync --force-design` (push over R001) and the resolution commands in finding 5. Rewrite adapters.md 2 loop as `compile -> lint -> read -> classify -> push -> regen -> read back -> record`.

### 2. [blocker] adapters.md 3 (bindings, "values never expressions"), R006 - import keeps SW equations as references, sync then flattens them in SW
`import` turns native expressions (`"B" = "A" * 2`, equation-driven dimensions) into `.cdt` references, but the emit contract writes only flat numbers or `ref` links to cadetta-emitted globals. After the first `sync` the user's SW equations are replaced by numbers, and a dimension that was equation-driven must have its equation removed before a value can be set. R006 covers a changed value, not lost structure; nothing says whether this is intended. This is the main adoption surprise for an existing part.
Fix: state it normatively: "Cadetta owns the dependency structure; sync replaces native expressions on bound locators with values or global links." Make R006 warning (not info) when a push removes a native expression or driving equation, listing the old expression. Add `sync --dry-run` (finding 6) that prints each such replacement. State push behaviour for an equation-driven dimension (remove equation, then set, or R010 refusal).

### 3. [blocker] adapters.md OQ-8, 2, 4.5 and obligations.md 2-3 - saving, unsaved changes and "file digest" are undefined though sync depends on them
OQ-8 (open) says refuse on unsaved changes and never save. But a successful `push` itself leaves the document modified and unsaved, so every sync ends in the state it would refuse to start from. The lock keeps a per-file last-sync digest, and the "CAD file reflects design" obligation is discharged by sync, yet the digest of an unsaved document does not exist. It is also unspecified whether the adapter attaches to a running SW or launches its own (invisible) instance, whether a closed file is opened and closed again, and what `read` does for a closed `.SLDPRT` (needs SW or the Document Manager API).
Fix: close OQ-8 with an ADR and write: (a) sync attaches to a running SW if present, else starts a hidden instance and closes only what it opened; (b) pre-flight: document dirty before push = R009 refuse; (c) after a successful regen+read-back the adapter saves only documents it modified (`[[adapter]] save = "after-sync" | "never"`, default `after-sync`), because the user has just asked sync to change them; with `never` the obligation stays open and says "unsaved"; (d) the lock records the saved file digest, and read of a file whose on-disk digest equals the lock skips the COM open.

### 4. [blocker] adapters.md 2, 6; obligations.md 2; sw-equations.md - on the zero-install equations path the model is never read back, so drift cannot exist and the obligation can never discharge
For `sw-equations` (emit+read only) `sync` degrades to `emit` plus instructions, and the obligation "CAD file reflects design" is discharged by "`sync` (or `emit` plus read-back)". Read of the equations file reads the text cadetta just wrote, not what SW holds. A user who edits a dimension in SW, or never relinks, is invisible. Also linked equations are not editable in SW, so the spec's drift story does not apply to this path at all.
Fix: say in adapters.md 2 and sw-equations.md that this adapter never discharges the "CAD file reflects design" obligation; it is `open (unverifiable)` unless a `drive`-capable adapter covers the same file, or the user runs `cadetta ack --role cad-linked`. Also document that `read` of this adapter exists to import an SW-exported equations list (Equations dialog > Export), which is how a user without COM gets observed IR.

### 5. [gap] adapters.md 4.5, config-cli.md 2 - no way to resolve drift in the CAD-to-design direction
Design-to-CAD is `sync --force-design`. For the other direction there is only `import`, which is documented as first-adoption scaffolding; contract 4.5 forbids writing source. The user's only recourse after R001 is to read the diagnostic and hand-edit the `.cdt`, losing tolerance, class, citation and emit point (observed 12.009 is the mid of `12mm H7`, not a new nominal).
Fix: add `cadetta import ADAPTER FILE... --update`: for already-bound paths whose observed value differs from the lock base, print a unified diff of `.cdt` literal edits (never applied without `--write`). Rules: skip and warn for a path whose literal carries a tolerance or fit (print the observed value, ask for a manual edit); flag a path that has a citation (S004-style "value no longer matches @cite"); never touch `let` or derived paths (report "derived; edit its sources"). After the edit, the next sync classifies as no-op.

### 6. [gap] config-cli.md 2 - `sync` and `import` have no options, output or exit semantics
`sync` is "the full loop" and `import` "proposes and scaffolds" with no flags, no text output shape, no definition of "changed params" (against which baseline?), and no dry run. The user cannot preview the first push over a legacy file, cannot sync a single file or path, and cannot see what happened.
Fix: specify at minimum `sync [--dry-run] [--only PATH_GLOB] [--force-design] [--no-regen] [ADAPTER...]`; text output: one line per locator (`push|skip|drift|fail  path  locator  old -> new`) then a summary and per-file regen status; JSON output: the list of those records plus diagnostics. "Changed" = emit value differs from the lock base (finding 1). Exit 1 if any diagnostic at or above `fail_on`, 2 for adapter-unavailable. Also state that the equations-file header `ir=blake3:` changes on any unrelated edit, so "writes nothing when no digest changed" (adapters.md 2) must compare emitted lines, not the header: either drop `ir=` from the header or exclude the header line from the no-op comparison.

### 7. [gap] adapters.md 3 and 5, config-cli.md 2, lints.md R - `import` is unspecified at the points a user touches
Missing: (a) the naming algorithm (how `Plate_Thk` or `plate thickness` becomes `Component.member`: component grouping per file, case normalisation per N001-N004, stripping unit suffixes, collision handling); (b) how the user "accepts" (CLI default output is JSON when not a TTY; no proposal file, `--accept`, interactive mode or per-item edit); (c) where scaffold and bindings land, merge behaviour when re-run (idempotent? appends? conflicts with the `init` hello-world), and whether `was` is used for later renames; (d) assemblies: how a `.SLDASM` maps to `assembly` plus `part` declarations and instance paths, and which file's dimensions an instance's bindings point to; (e) dimension tolerances, driven (reference) dimensions and configurations (OQ-4: every SW part has a Default configuration, and dimensions and properties are per configuration, but the locator has no configuration field); (f) custom properties (kind `property`): they are text, may be `$PRP:` or equation-linked, and carry no unit, yet the model has no rule for typing them or for the "Text is not emitted" case.
Fix: add an "Import" subsection to config-cli.md or adapters.md: `import` writes `build/import/proposal.toml` (rows: native name, proposed path, proposed `Type`, value, unit, status accept|rename|skip); `cadetta import --apply` writes `bindings/<adapter>.toml` and `cad/imported/<File>.cdt` (never overwriting; second run adds only unseen locators and reports already-bound ones as unchanged). Naming: component = file stem (UpperCamel), member = snake_case of the native name with unit suffix stripped, collisions suffixed and flagged. Configurations: 0.1.0 binds the active configuration only and records it in the locator (`config = "Default"`); import warns (info) when other configurations exist. Properties: bind only as `Text`/Count/Quantity with explicit `native_unit`; a `$PRP`/linked property imports as skipped with a reason.

### 8. [gap] config-cli.md 1-2 - `init` does not know about SOLIDWORKS and its scaffolding must be cleaned up by hand
`init` writes "a complete file" whose adapter examples are `sw-equations` and `freecad`; the COM adapter (command, `files` globs for `*.SLDPRT`/`*.SLDASM`, how it is installed, Windows-only `platforms`) has no entry or install story (bindings.md only says `pip install cadetta`). The hello-world `.cdt` collides with imported names and trips U001/I004 noise, forcing the "clean up the scaffolded .cdt" step. "Safe to repeat" does not say it will not overwrite an edited `cadetta.toml`.
Fix: `cadetta init [--adapter solidworks|freecad|sw-equations] [--bare]`: `--bare` writes no sample `.cdt`; `--adapter solidworks` writes the `[[adapter]]` block (`command = ["cadetta-solidworks"]`, `files = ["**/*.SLDPRT", "**/*.SLDASM"]`, `save`, `native_unit`) and prints the install line (`pip install "cadetta[solidworks]"`, which pulls pywin32 and must be run in the Windows interpreter). Repeat run: create missing files only, never rewrite an existing one, exit 0 with an info line per skipped file. Namespace defaults to the directory name, normalised, and is echoed.

### 9. [gap] adapters.md 4 and 5, lints.md R-rules - failure modes have no codes, no atomicity and no exit semantics
SW not running or not installed, wrong platform, adapter version mismatch (OQ-7), file locked by another process or read-only, document dirty, locator not found, dimension driven or suppressed, rebuild error, and a push that fails halfway are all unspecified. `push` returns only "diagnostics"; the only relevant codes are R003 and R004. config-cli.md has a single exit code 2 for "usage or I/O error". `check` also reads adapters (config-cli.md 2) but nothing says what it does on Linux CI for an adapter whose `platforms` exclude it.
Fix: add rules: R008 adapter-unavailable (not installed, wrong platform, version mismatch; check skips and reports info, sync fails exit 2), R009 file-busy (dirty, locked, read-only; refuses before any push), R010 push-rejected (driven or suppressed dimension, equation conflict, unit conflict). Atomicity: pushes are per document; adapters MUST attempt to snapshot the previous values of a document and restore them on R004 (SW: `EditRebuild3` failure then set old values; if restore fails, say so); the lock is updated only for locators whose read-back matched, so a partial sync reconverges on the next run. `push` result must be a per-locator status list, not just diagnostics. Platform mismatch in `check`: use the lock base as observed and mark the drift obligation `unverified`.

### 10. [gap] adapters.md 3 (`ref_to`, mangling), sw-equations.md 1 - one SW target, two adapters, no shared naming or bindings
SW users have `sw-equations` and the COM `solidworks` adapter. Bindings live in `bindings/<adapter>.toml`, so the same global is bound twice; "the emitter never writes dots" (sw-equations.md) vs "where the target allows dots" (adapters.md 3) leaves it open whether the COM adapter creates `Axle.end_diameter` or `Axle__end_diameter`, so switching adapters renames globals in the user's part. Also dimension names `D1@Boss-Extrude1@CoverPlate.SLDPRT` are the equations-file form; the COM API and an assembly-context dimension (component in an assembly) use different spellings, and instance paths of an array of one part (`Rover/wheel[2]`) have no rule for which component instance a locator addresses.
Fix: add a "SOLIDWORKS naming" section to sw-equations.md that both adapters MUST follow (mangling is always `__`; dimension locator grammar for part, assembly and in-assembly component contexts with a `component = "wheel<2>"` field for instances) and allow `bindings/solidworks.toml` to be shared via `[[adapter]] bindings = "bindings/solidworks.toml"`.

### 11. [gap] obligations.md 5.1, adapters.md 3, language.md `part` - part swap ends at the preview; the assembly in SW is not updated or checked
`impact --swap` lists "CAD files to re-sync" with changed values. But the real swap in SW (Replace Components, mates repaired) is manual and unseen: bindings of `Rover/wheel[2].hub_bore` still point at the old part's file, so the next sync pushes the new part's numbers into the old part (or fails R003), and nothing reports that the assembly still contains the old component.
Fix: (a) bindings for an interface-typed slot are keyed on the slot path plus an `alternate` field (`for = "Colson2Series"`), so a swap changes which locator set is active; (b) `read` of an assembly records the component's file name, and a new R rule (R011 component-mismatch, warning) fires when the file instantiated in the assembly is not the file bound to the slot's primary; (c) the `impact --swap` section 5 lists the replace-component action explicitly ("replace wheel<2> with Colson2Series.SLDPRT in Rover.SLDASM").

### 12. [polish] geometry.md 6, lints.md R007 - coordinate bindings ignore sign, direction and what the dimension is measured from
Point coordinates (`holes[1].x = -25mm`) bind to sketch dimensions that SW stores as positive distances with direction from the sketch geometry; "measured from the datum" is only true when the sketch is on the datum plane and the dimension runs from the origin. `import` can only create scalar parameters, never `Point2` values (geometry "never reconstructs geometry"), so a migrated hole pattern stays scalars and the alignment checks of geometry.md 5 are unreachable without manual rewriting.
Fix: add to geometry.md 6 a binding field `sign = -1` (or `direction`) on coordinate locators with read applying it, state that R007 also covers "dimension not measured from the sketch origin" where the adapter can tell, and add one sentence to the import subsection: imported dimensions are scalars; converting a set of them to a `Point2` array is a manual refactor that keeps the existing locators via `#[native]`/binding re-keying.
