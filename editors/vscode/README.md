# Cadetta for VS Code

Syntax highlighting for `.cdt` files (grammar generated by
`editors/generate.py`), language configuration (`//` comments, brackets,
auto-closing), a minimal language client that starts `cadetta lsp`
(diagnostics, formatting, hover as `why`, the `impact` code lens and go to
definition; completion is not provided), the `$cadetta` problem matcher and a `cadetta` task type.

## Settings

- `cadetta.path` (default `cadetta`): the executable; the client runs
  `<path> lsp`.
- `cadetta.lsp.enabled` (default `true`): turn the language client off to
  use only the grammar and the check task below.

The client activates on `onLanguage:cadetta`. Changing either setting
restarts it. Logs are in the Output panel, channel "Cadetta".

## Install (not published)

Build and install a VSIX:

    cd editors/vscode
    npm ci
    npm run compile
    npx @vscode/vsce package
    code --install-extension cadetta-0.1.0.vsix

(or Extensions > ... > Install from VSIX). Needs Node 18+ and VS Code 1.91+.
Dependency versions are pinned in `package.json` and `package-lock.json`.

## Check task (fallback)

Without the language server, run the check as a task.

In `.vscode/tasks.json`:

    {
      "version": "2.0.0",
      "tasks": [
        {
          "label": "cadetta check",
          "type": "shell",
          "command": "cadetta check --format short",
          "problemMatcher": "$cadetta",
          "group": "build"
        }
      ]
    }

The `cadetta` task type (`"type": "cadetta", "command": "check"`) is declared
for task providers; the shell form above works without one.
